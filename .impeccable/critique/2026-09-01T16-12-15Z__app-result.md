## Design Specificity Verdict

**Split — an authored model wrapped in interchangeable chrome.**

The model could not be lifted into another app: the declared-view contract, the deliberate pending/empty split (layoutModel.ts:10-15), the one panel contract three layouts share (panelDeck.ts), and copy like "nothing survived — this hop dropped the section the chain asked it for".

The chrome is category furniture: `max-w-6xl` centering on a machine PRODUCT.md declares wide-desktop-only, a rounded-2xl bordered form card, a vertical radio list, an active:scale-95 black pill, rounded-full mode chips. The distance from "well-designed terminal emulator" is entirely in the frame, not the content.

**Deterministic scan:** detect.mjs --json app/result components/result → 0 findings, verified real (calibration runs fired rules elsewhere; no ignore config, no disable comments). Caveats: the detector only regex-matches .tsx, so "clean" = "no known bad string patterns"; exit code is not a findings signal for this binary. One adjacent real finding: overused-font at globals.css:18 — `body { font-family: Arial, Helvetica, sans-serif }` overrides the Geist loaded in layout.tsx:9-17. The whole app renders in Arial.

**Visual overlays:** none. No browser automation exists on this machine (no Playwright/Puppeteer, empty ~/.cache/puppeteer Chrome dirs, no system Chrome, no browser MCP). ## Overall Impression

The seam work is good — LayoutModelView dispatches three layouts and mounts compare once, so story 13 is structurally true. What's missing is everything around the run: the surface never says the run finished or failed, and on the flagship chain the signature signal doesn't fire.

## What's Working

1. LayoutModelView as single dispatch (LayoutModelView.tsx:33-39) — compare mounted once for all layouts.
2. The pending/empty split with its own copy — domain knowledge, not defaults.
3. Shared-mode compare inverts the marks (CompareOverlay.tsx:15-20): agreement recedes, divergence bolds.

## Priority Issues

**[P0] An errored or skipped hop is told a false story.** layoutModel.ts:61
`!output ? 'pending' : text.trim() === '' ? 'empty' : 'filled'` ignores output.status ('success'|'error'|'skipped', types.ts:197). workspace/logs/2026-09-01-qxtuNx/00-first.md is a real status:error, tokens_out:0 hop — it renders "nothing survived — this hop dropped the section the chain asked it for". A gate-skipped node gets the same sentence.
Why: this is the one defect that makes the view lie, against a product whose tier-2 promise is that content is knowable from the log.
Fix: branch on output.status first; add errored and skipped panel states with copy in the same voice.
Command: /impeccable harden

**[P0] Nothing on the result surface knows the run ended, or failed.** RunFrame.tsx:34-49, page.tsx:203
RunFrameModel has no status. running and error live only in the page and render inside the form card far above the result.
Why: real hops run 27–165s. On failure the counter freezes, panels stay "waiting" forever, no log link appears, and the message is off-screen.
Fix: add status: 'running'|'done'|'failed' and error? to RunFrameModel, render beside the elapsed counter; give a settled pending panel copy that says "never ran".
Command: /impeccable harden

**[P1] The timeline's signature signal is flat on the chain it was built for.** Timeline.tsx:10
growOf = Math.max(panel.lines, 1). Verified against workspace/logs/2026-09-01-iPyX-u/: the three socket:summary panels are 6, 6, 6 lines (the agent contract mandates a bulleted ## Summary) while character counts are 611 → 501 → 469. The run shrank; the timeline draws three identical boxes. User story 6 does not render.
Fix: carry chars on LayoutPanel and scale by it (dampened, readable floor); show both numbers in the corner badge, which currently shows a bare unitless integer.
Command: /impeccable layout

**[P1] Content volume fights declared emphasis.** Timeline.tsx:25, layoutModel.ts:99
wrong-audience.md declares `rewritten` then `assumed knowledge`; the chain file says "The rewrite is scaffolding for that list." Width gives the scaffolding the row and squeezes the finding — while emphasis:'last' marks the finding as the point. domain-transplant.md is the same shape.
Fix: let emphasis win the width contest — floor an emphasised panel at a fixed share before volume divides the remainder.
Command: /impeccable layout

**[P2] Five prose panels in 1152px, and a compare that can't read them.** page.tsx:118, Columns.tsx:27, compareModel.ts:37-48
five-personas is 5 branches + 1 join → ~208px per column at fixed h-40, a 6-line preview of a 5KB take, hard-clipped with no fade. Base-mode compare runs character-level diff_main over two independently generated texts — on the two chains whose files say "Tick both and compare".
Fix: (a) drop max-w-6xl for the result region only; PRODUCT.md licenses the horizontal room. (b) line-mode the base diff, or default to shared when >2 panels are ticked.
Command: /impeccable adapt
